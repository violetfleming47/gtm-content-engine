## Specifications

**Length:** 2,000–4,000 words (8–16 pages designed).

**Perspective:** Third person or first-person plural ("we" for [YOUR COMPANY]-attributed insights). If [YOUR FOUNDER] writes an executive foreword, that section uses first person singular and follows his voice file.

**Design:** Branded template. Pull quotes, data callouts, diagrams. Never a wall of text.

**Gating:** Typically gated behind a form for lead capture.

## Structure

```
1. TITLE PAGE
   Title (benefit-driven, not feature-driven)
   Subtitle / descriptor
   [YOUR COMPANY] branding + date

2. EXECUTIVE SUMMARY (half page)
   The entire argument in 150–200 words.
   Reader should be able to stop here and get the core insight.

   📊 GRAPHIC TRIGGER: Data callout box
   Pull one headline stat from the paper and display it as an oversized
   data callout alongside the summary. This is the number the reader
   remembers and screenshots.

3. THE PROBLEM (1–2 pages)
   Define the structural challenge. Use data.
   Make the reader feel the cost of inaction.
   No product mention yet.

   📊 GRAPHIC TRIGGER: Problem visualisation
   If the problem involves a process (e.g., vendor onboarding timelines),
   create a simple flow diagram or timeline showing the current broken
   state. If it involves scale (e.g., how many pilots fail), create a
   data visualisation. The reader should be able to see the problem,
   not just read about it.

4. WHY CURRENT APPROACHES FAIL (1–2 pages)
   Dismantle the status quo. Be specific.
   Name the failure modes the reader will recognise.

   📊 GRAPHIC TRIGGER: Comparison or failure matrix (optional)
   If there are 2–4 common approaches that each fail differently,
   a comparison table or matrix makes this land faster than prose.
   Only create if the comparison is genuinely multi-dimensional.
   Don't force a table for a single-axis argument.

5. THE FRAMEWORK / SOLUTION APPROACH (2–3 pages)
   Introduce the structural answer ([YOUR CATEGORY ABBREV], decision infrastructure, etc.)
   Evidence: platform data, case signals, benchmarks.

   📊 GRAPHIC TRIGGER: Framework diagram (required)
   This section must include a framework or architecture diagram.
   This is the centrepiece visual of the paper — the thing that gets
   reused in sales decks, referenced in follow-up emails, and
   screenshot by the reader. It should explain the structural
   solution visually. Build it to stand alone.

   📊 GRAPHIC TRIGGER: Data callout boxes
   For each key evidence point (platform stat, benchmark, case signal),
   create an inline data callout — single stat, large font, one-line
   context. Aim for 2–3 across this section.

6. IMPLEMENTATION / WHAT GOOD LOOKS LIKE (1 page)
   Practical guidance. Maturity stages or a checklist.
   [YOUR COMPANY]'s role introduced naturally, not pitched.

   📊 GRAPHIC TRIGGER: Maturity model or checklist visual (optional)
   If the implementation guidance uses stages (e.g., crawl/walk/run,
   maturity levels), visualise it. A horizontal progression or tiered
   diagram. If it's a checklist, a styled checklist graphic is cleaner
   than inline text.

7. CONCLUSION + CTA (half page)
   Reframe the argument. One strong closing statement.
   CTA: demo, conversation, assessment.
```

---

## Graphic Density Rule

Every 2-page spread must include at least one visual element. This can be any combination of:

- Framework or process diagram
- Data callout box (single stat, oversized)
- Comparison table or matrix
- Pull quote (styled as a visual block, not inline text)
- Mini infographic explaining a sub-concept

If a 2-page spread has no visual element, something is missing. Either the content needs a supporting graphic, or there's a pull quote worth extracting.

## Section Rules

- Lead every section with the insight, not the background. The first sentence of each section should be the sharpest.
- Data before opinion. Always.
- One core argument per white paper. Don't try to say everything.
- Every diagram or framework should be reusable in sales conversations.
- Pull quotes should be strong enough to use as standalone LinkedIn posts.
- [YOUR COMPANY] is mentioned in the second half only, and as the enabler, not the hero.
- Apply all voice and positioning rules from voice-profile.template.md, including the review test, word bans, and the genericness test.
