## Specifications

**Length:** 400–1,000 words.

**SEO:** Every post targets a primary keyword. Title and H2s should be search-friendly.

**Design:** Hero image, in-line images or diagrams where useful. Scannable layout.

**Distribution:** [YOUR COMPANY] blog. Repurpose for social via the LinkedIn structure files (01 or 02).

## Blog Post Types

### Type A — Explainer / Educational

Breaks down a concept, trend, or category for the reader. Positions [YOUR COMPANY] as the expert.

```
HEADLINE (keyword-driven, clear benefit)

   📊 GRAPHIC TRIGGER: Hero image (required)
   Explainers should lead with a concept graphic as the hero —
   a diagram, labelled visual, or framework that previews what
   the reader is about to learn. This makes the post more
   shareable and gives the reader a reason to stay.

INTRO (1 paragraph) — Why this matters right now.

BODY (3–5 sections with H2 subheadings)
  Each section = one sub-idea, self-contained.
  Use examples, not abstractions.

   📊 GRAPHIC TRIGGER: Inline diagrams (1–2, where applicable)
   If a body section explains a process, model, or architecture,
   create an inline mini infographic or diagram for that section.
   Each diagram should explain its section's concept visually.
   Not every section needs one — only where the visual adds
   understanding the text alone doesn't.

TAKEAWAY (1 paragraph) — What the reader should do next.

CTA — Related content, demo, or download.
```

---

### Type B — Opinion / Hot Take

A clear position on something happening in the industry. Shorter, sharper, more opinionated.

```
HEADLINE (declarative, takes a side)

   📊 GRAPHIC TRIGGER: Hero image (required)
   Branded graphic with the headline statement. Navy background,
   White/Cyan text. Keep it bold and simple — the opinion is the
   visual. No diagrams needed.

HOOK (1–2 sentences) — The event or trigger.

ARGUMENT (3–4 paragraphs) — Evidence-backed position.

   📊 GRAPHIC TRIGGER: Data callout (if applicable)
   If the argument hinges on a specific stat or data point, create
   an inline data callout graphic. If the argument is purely
   qualitative, skip it.

SO WHAT (1 paragraph) — Why this matters to the reader.

CLOSE — Reframe.
```

---

### Type C — Product / Use Case

Shows how [YOUR COMPANY] solves a specific problem. Customer-problem-first, never feature-first.

```
HEADLINE (problem-driven)

   📊 GRAPHIC TRIGGER: Hero image (required)
   Two options:
   a) Before/after visual showing the problem state vs. the
      [YOUR COMPANY]-enabled state. Strongest option for use cases.
   b) Outcome stat graphic — the headline number displayed large.

THE PROBLEM (1–2 paragraphs) — What the buyer deals with.

THE APPROACH (2–3 paragraphs) — How [YOUR COMPANY] addresses it.

   📊 GRAPHIC TRIGGER: Process or architecture diagram (recommended)
   If the approach involves a workflow, integration, or
   multi-step process, create an inline diagram showing how
   it works. This is what the reader forwards to their team.

THE RESULT (1 paragraph) — Outcome or benchmark.

   📊 GRAPHIC TRIGGER: Outcome data callout (recommended)
   Single stat, oversized, with one line of context.
   e.g., "4x faster vendor onboarding" or "60% reduction
   in compliance review cycles."

CTA — Demo, case study, or conversation.
```

## Writing Rules

- Every blog post must be scannable. A reader skimming the H2s should get the argument.
- No filler paragraphs. If a section doesn't advance the point, cut it.
- Internal links to other [YOUR COMPANY] content where relevant (builds SEO and time-on-site).
- End with a genuine CTA, not a generic "contact us." Be specific about what the reader should do.
- Apply the hook banned patterns from the relevant LinkedIn structure file. The same traps apply to blog intros.
- Apply all voice and positioning rules from the paired voice file (07 or 08), including the review test, word bans, and the genericness test.

## SEO Notes

- Primary keyword in the title, first paragraph, and at least one H2.
- Meta description: 150–160 characters. Restate the core argument, not the title.
- URL slug: short, keyword-rich, no dates unless time-sensitive.
- Alt text on all images and graphics: descriptive, keyword-aware where natural. This includes any graphics produced by the graphics store.
