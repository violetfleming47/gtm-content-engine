## Specifications

**Byline options:** First person ([YOUR FOUNDER] byline) or third person / "we" ([YOUR COMPANY] byline). The voice file for the chosen byline governs all linguistic decisions.

## Structure

```
1. HEADLINE
   Specific and benefit-driven. Avoid clickbait.
   Test: would a CTO click this in a newsletter?

   📊 GRAPHIC TRIGGER: Hero image (required)
   Every article needs a hero image. Two options:
   a) If the article's core argument can be captured in a single
      visual (a stat, a framework, a before/after), create a
      concept graphic as the hero. This is the stronger option.
   b) If the argument is abstract or opinion-driven, use a branded
      graphic with the headline text styled over a Navy background.
   Never use stock photography as the hero.

2. OPENING HOOK (1–2 paragraphs)
   Lead with the tension, pattern, or data point.
   Apply the hook rules from the relevant LinkedIn structure file
   (01 or 02) — the same banned patterns apply here.

3. THE ARGUMENT (3–5 paragraphs)
   One core thesis, built with evidence.
   Each paragraph should advance the argument, not repeat it.
   Subheadings allowed (max 2–3) to guide the reader.

   📊 GRAPHIC TRIGGER: Concept diagram or data callout (if applicable)
   If the argument introduces a framework, model, or process,
   create an inline diagram. If the argument hinges on a key stat,
   create a data callout graphic.
   Not every article needs an inline graphic. Trigger only when the
   visual would make the argument land faster than prose alone.

4. THE IMPLICATION (1–2 paragraphs)
   What this means for the reader's organisation.
   Make it actionable or at least thought-provoking.

5. CLOSE (1 paragraph)
   If [YOUR FOUNDER] byline: reframe.
   If [YOUR COMPANY] byline: reframe + optional CTA.
```

---

## Graphic Decision Logic

Articles are lighter on visuals than white papers. Use this checklist:

| Condition | Graphic action |
|-----------|---------------|
| Article introduces a framework or model | Create an inline diagram. Required. |
| Article's core argument hangs on 1–2 key stats | Create a data callout graphic. Recommended. |
| Article is a comparison (X vs Y, old way vs new way) | Create a comparison visual. Recommended. |
| Article is pure opinion / commentary with no data | Hero image only. No inline graphics. |
| Article references a process or workflow | Create a simple flow diagram. Required. |

## Writing Rules

- One argument. If you have two, write two articles.
- Subheadings are signposts, not decorations. Use them to help scanning, not to break up text arbitrarily.
- First 100 words decide if the reader stays. Front-load the value.
- Avoid "step 1, step 2, step 3" formats unless genuinely instructional.
- No throat-clearing intros. The first sentence should be the hook, not context-setting.
- If submitting to an industry publication, match their house style for formatting but maintain the voice from the paired voice file.
- Apply all voice and positioning rules from the paired voice file (07 or 08), including the review test, word bans, and the genericness test.
